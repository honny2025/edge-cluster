# 手机边缘计算集群管理平台：优化后产品与技术规格

## 1. 优化后的产品定位

平台把局域网或公网中的 Android 手机统一抽象为“边缘计算节点”。每个节点运行 Agent，负责设备状态采集、模型文件管理、推理服务托管和平台指令执行；平台负责节点接入、资源编排、模型分发、服务管理、API 统一入口、监控告警和任务审计。

最终闭环为：**手机接入 → 节点监控 → 模型下发 → 服务启动 → API 调用 → 运行监控 → 故障恢复 → 跨公网管理**。

当前压缩包已经覆盖“局域网发现、心跳、指标采集、首页看板、告警”的 M1/M2 范围；模型库、模型下发、服务托管、API Gateway、P2P/中继属于后续版本，不能在产品说明中继续表述为已完成能力。

## 2. 版本路线

### V0.2（当前基础版，M1/M2）

- 局域网 UDP 自动发现和手工 URL 接入
- Agent WebSocket 长连接、心跳、自动重连
- 节点在线/离线/从未接入/指标陈旧状态
- CPU、内存、存储、温度、电池等可获得指标采集
- 节点列表、节点详情、历史曲线、集群汇总、告警
- 模拟节点和一键启动脚本

### V0.3（模型库与可靠下发）

- 模型上传、删除、版本、元数据和 SHA-256 校验
- HTTP Range 断点续传、限速、重试、校验失败回滚
- 单节点/批量部署任务、进度、暂停、重试、取消
- Agent 本地模型目录、磁盘配额和并发下载限制
- 部署任务持久化，平台重启后可恢复任务状态

### V0.4（模型服务托管）

- 一个节点运行多个模型服务
- 服务启动、停止、重启、滚动更新、崩溃拉起
- 进程隔离、端口分配、健康检查、日志查看
- 模型参数、环境变量、线程数、设备类型等配置
- 服务资源指标与节点指标关联

### V0.5（统一 API）

- OpenAI-compatible Chat/Completions/Embeddings 接口
- VLM 文本+图片接口
- OCR、分类、检测等统一 REST 接口
- Endpoint、节点、模型、服务状态统一展示
- API Key、限流、超时、重试、调用审计

### V0.6（跨公网与生产化）

- 出站优先的 P2P 通道（手机不暴露入站端口）
- P2P 失败时自动切换中继
- 节点身份、设备密钥、证书轮换
- 多租户/角色权限、TLS、审计、备份和升级

## 3. 统一核心对象

### Node

`node_id`、名称、型号、SoC、Android 版本、Agent 版本、局域网 IP、连接方式、状态、最后心跳、在线时长、当前任务、资源总量、资源使用量、能力标签。

### Model

`model_id`、名称、版本、类型、框架、文件大小、SHA-256、架构、所需内存、所需加速器、创建时间、状态。

### Deployment

`deployment_id`、模型版本、目标节点、状态、百分比、已下载字节、安装阶段、错误码、重试次数、创建/开始/完成时间。

### Service

`service_id`、节点、模型版本、服务类型、端口、Endpoint、启动参数、进程号、状态、健康状态、资源限制、最近日志、请求统计。

### Alert/Event

事件类型、级别、节点/服务/任务关联、首次发生、最近发生、次数、确认人、恢复时间、原始上下文。

## 4. 节点状态与任务状态

节点状态固定为：`never_seen`、`online`、`offline`、`stale`、`error`。服务状态固定为：`stopped`、`starting`、`running`、`degraded`、`error`、`stopping`。部署状态固定为：`queued`、`downloading`、`verifying`、`installing`、`ready`、`failed`、`cancelled`。

状态切换必须由后端统一执行，Agent 上报只提供事实。所有状态变化写入事件表，避免依赖前端推断。离线或陈旧节点不得参与当前资源汇总，也不得下发最后一次旧指标。

## 5. 通信与安全优化

- 控制通道：Agent 主动建立 WebSocket；消息必须带 `message_id`、时间戳、协议版本和幂等键。
- 文件通道：模型使用 HTTPS/HTTP Range 下载，不通过 WebSocket 传大文件。
- 局域网发现：UDP 仅用于发现，不携带 token；发现响应只返回平台地址和临时连接信息。
- 公网连接：Agent 出站连接到信令服务；优先 P2P，失败转中继。
- 身份认证：开发环境 token；生产环境每个 Agent 独立设备密钥，平台签发短期访问令牌。
- 传输保护：公网必须 TLS；模型下载校验 SHA-256；命令带过期时间和幂等键。
- 权限控制：平台管理员、运维、只读观察者至少三种角色。

## 6. API 设计

基础接口保留现有 `/api/v1/system/*`、`/api/v1/nodes/*`，新增：

- `POST /api/v1/models`、`GET /models`、`DELETE /models/{id}`
- `POST /api/v1/deployments`、`GET /deployments/{id}`、`POST /deployments/{id}/retry`
- `GET/POST/PATCH /api/v1/nodes/{id}/services`
- `POST /services/{id}/start`、`stop`、`restart`
- `GET /services/{id}/logs`、`GET /services/{id}/metrics`
- `POST /api/v1/inference/{service_id}/...`
- `GET /api/v1/events`、`POST /alerts/{id}/ack`

所有写操作返回任务 ID，前端通过 WebSocket 订阅任务进度；长耗时操作不得同步阻塞 HTTP 请求。

## 7. Dashboard 优化

首页按四层展示：

1. 集群层：节点数、在线率、可用 CPU/GPU/NPU、内存/存储池、告警数。
2. 任务层：部署中、失败、最近完成、队列等待时间。
3. 服务层：运行模型数、请求量、吞吐、P50/P95 延迟、错误率。
4. 设备层：温度、功耗、陈旧指标、异常节点和最近事件。

无数据必须显示“—”或断点，不能补 0。趋势图区分实时值、历史值和估算值。离线节点指标为空，历史曲线仍保留。

## 8. Agent 优化要求

- 使用 supervisor/守护线程管理采集器、控制通道、下载器和服务管理器。
- 断线采用指数退避并设置最大间隔；恢复连接后补发未确认事件。
- 所有命令可重试且幂等；服务进程异常退出自动回收端口并按策略拉起。
- 模型下载支持断点、校验、临时文件和原子改名；磁盘不足提前拒绝。
- Android 侧明确标注 Termux 的后台限制，并提供电池优化检查和保活诊断。

## 9. 当前版本必须修正的产品表达与问题

1. 文档中将模型下发、服务管理和 API 对外服务标为“后续能力”，避免用户误解。
2. 默认 token 仅用于开发环境；首次启动强制提示更换。
3. 提供快速离线和抗抖动两种离线策略，明确 15 秒阈值与确认次数的关系。
4. 一键启动脚本增加离线依赖缓存或清晰的依赖预检，避免网络受限时运行到中途才失败。
5. 将服务列表、部署记录、API Endpoint 以空状态明确标注“功能尚未启用”。
6. 增加版本、Agent 兼容矩阵和数据库备份/迁移说明。

## 10. 分阶段验收标准

- **接入**：新节点 30 秒内出现；断网后按策略进入 offline；恢复后复用原 node_id。
- **指标**：连续 10 分钟采样时间单调递增；缺失值为 null；离线节点不参与汇总。
- **模型**：100MB 文件支持断点续传；SHA-256 不一致时任务失败且不覆盖旧版本。
- **服务**：启动、停止、重启幂等；进程崩溃可检测；健康检查失败产生告警。
- **API**：请求可追踪到 service/node/model；超时、错误率、P95 延迟可查询。
- **安全**：未认证写操作全部拒绝；公网通道必须 TLS；命令过期后拒绝执行。
- **可靠性**：平台重启后任务和节点状态可恢复；Agent 重启后无重复节点和幽灵任务。

## 11. 建议开发顺序

先完成 V0.3 的模型库和部署任务，再做 V0.4 服务托管；两者稳定后统一 API，最后实施公网 P2P/中继。这样可以复用现有节点、WebSocket、指标和事件基础，减少一次性改动造成的状态和数据一致性问题。
