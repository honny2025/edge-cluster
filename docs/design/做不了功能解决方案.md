# 做不了的功能 & 解决方法

> 本文档对应「你认为做不了的功能」。先说清楚一件事：**下面绝大多数不是平台代码缺陷，而是受限于
> Android 系统权限 / 网络环境 / 需要真人操作**。平台侧的逻辑已经写好，缺的是「让它能拿到数据/让真人授权」这一步。
> 每一项都给了可落地的解决方法。

---

## 总览

| # | 现象（「做不了」） | 真因 | 状态 | 解决路径 |
|---|---|---|---|---|
| 1 | CPU / GPU / NPU 使用率拿不到真值 | Android SELinux 屏蔽 `/proc/stat`、NPU 节点等，非 root 读不到 | 平台已留接口，等权限 | root 或 Shizuku（见 §1） |
| 2 | 真机上跑不起模型推理服务 | 平台指令能下发，但手机 Termux 里 `agent.py` 没在跑 | 平台逻辑已验证通过 | 用 Codex 指南把手机接进来（见 §2） |
| 3 | 网关没有限流/负载均衡/熔断 | §7 要求的是「转发 + 计时 + 计数」，这三样都已实现；限流等属高阶能力，需求书未要求 | **鉴权已做**；限流/负载均衡明确不做 | 见 §3 |
| 4 | 平台不会自动改防火墙/提权 | 安全边界，不该自动做 | 设计如此 | 人手动放行（见 §4） |
| 5 | 校园网/热点下 WS 注册失败（客户端隔离） | AP 隔离导致同网段不可达 | 已踩过并绕过 | 用电脑热点 / 手动填 IP（见 §5） |

## §1 CPU / GPU / NPU 真值（Android 权限问题）

### 根因（实测）
- 在荣耀 X70 上实测 121/121 次采样，CPU/GPU/NPU 使用率字段**全部为 null**。
- 非 root 的 Termux 下：`/proc/stat`（CPU 累计）、`/sys/devices/.../gpu/...`、`/sys/class/thermal/*`
  部分可读、部分被 SELinux `u:object_r:...` 拒读；NPU 使用率根本没暴露给用户态。
- 平台侧 `agent_metrics.py` **已有降级链**：拿不到就留空（显示「—」），不会造假成 0。所以这是「数据缺失」不是「平台 bug」。

### 解决方法

#### 方案 A：root（Magisk）——最彻底
1. 手机解锁 Bootloader → 刷 Magisk → 重启。
2. Termux 装 `tsu`：`pkg install tsu`。
3. 用 `sudo` 跑采集：
   ```bash
   tsu -c 'cat /proc/stat'                 # CPU 累计，自己算差分
   tsu -c 'cat /sys/devices/platform/soc/.../gpu/gpu_busy'  # GPU 占用（路径机型相关）
   ```
4. 把 root 采集逻辑接进 `agent_metrics.py`（项目已留 `AgentMetrics.collect()` 扩展点）。

#### 方案 B：Shizuku（免 root，推荐普通用户）
1. 手机装 **Shizuku** + 电脑 `adb` 跑一次 `adb shell shizuku_server`（无线调试授权，一次即可）。
2. Termux 装 `shizuku` 命令行 / 用 `rish` 以 **shell(uid 2000)** 权限读系统文件，绕过 app 级 SELinux：
   ```bash
   # 经 Shizuku 以 shell 身份读取（比 Termux app 权限高）
   rish -c 'cat /proc/stat'
   rish -c 'cat /sys/class/thermal/thermal_zone0/temp'
   ```
3. 改造 `agent_metrics.py`：优先 `rish`/root，失败回退 `termux-api`/`sysfs`，再失败留空。

#### 方案 C：退路（不拿真值也不造假）
- 温度：`termux-battery-status`（电量/温度，无需 root）。
- 内存/存储/网络/进程：现有逻辑已正常。
- GPU/NPU：在控制台明确标注「—（需 root/Shizuku）」，见 `需求覆盖评估与实施计划.md` 的降级约定。

> 结论：**平台永远显示真实值或留空，绝不为 0**。要真值就按 A/B 给 Agent 提权。

## §2 真机上跑模型推理服务

### 根因（其实不是「做不了」）
- 上一轮已做**端到端验证**：模拟 Agent + 真实 HTTP 服务，跑通
  `建服务 → 资源准入 → 启动下发并回写 running → 取日志 → 网关转发 → 探活 → 停止`。
- 唯一卡点：**手机 Termux 里 `agent.py` 实际没在跑**。平台指令能发，但没人把 Agent 接进来。

### 解决方法
- 用本包里的 **`CODEX_TERMUX_GUIDE.md`** 把每部手机接进来即可。接好后：
  - 控制台「模型库」上传模型 → 「部署」选节点 → 平台下发 → Agent 后台下载（带进度条）→ 拉起推理子进程。
  - 推理框架（llama.cpp / ONNX Runtime / 厂商 SDK）需手机端能跑——这是**模型服务自身依赖**，平台负责传模型 + 启进程 + 探活 + 取日志。
- 一句话：**这功能已经能用了，缺的是「按指南把手机接进来」这一步**。

## §3 API 网关高阶能力（限流 / 负载均衡 / 熔断）

### 当前状态

**需求书 §7 要的三件事已经全部做完**：

| 能力 | 状态 | 落点 |
|---|---|---|
| 转发（含 OpenAI 兼容请求按原样透传） | ✅ 已实现 | `server/app/services/gateway.py` `_forward` |
| 计时（每次调用的耗时，可算平均延迟） | ✅ 已实现 | `GatewayStats.record()` 记录 `ms`，`avg_ms()` 出均值 |
| 计数（请求量 / 成功失败数） | ✅ 已实现 | `GatewayStats.get()`，经 `/gateway/{service_id}/stats` 暴露 |
| **鉴权** | ✅ **已实现** | `routes_gateway.py` 的路由挂了 `dependencies=[Depends(require_token)]` |

### 明确不做的（不是「待排期」）

| 能力 | 为什么不做 |
|---|---|
| 限流 | 单团队局域网自用，没有多租户互抢带宽的场景。真要做，用 Nginx / Caddy 在反向代理层做更合适，不必写进平台 |
| 负载均衡 | 需求书里一个服务对应一个节点上的一个进程；「一服务多实例分发」会把模型语义搅乱（同一个 service_id 打到不同模型的手机上，结果不可复现） |
| 熔断 | 同上。探活 + 看门狗已经能把「服务不健康」如实反映到状态机上 |

> 这些不是「加功能」，是**超出需求边界**。真需要，放在网关前面那一层做。

### 如果以后确实要加

网关的转发路径已经收敛在 `services/gateway.py` 一处，`_forward` 前插入校验、
`GatewayStats` 旁边挂 `RateLimiter` 都是局部改动，不影响现有语义。

## §4 防火墙 / 提权

### 根因
平台**不应该**自动改系统防火墙或提权——这是安全红线，也是设计边界。

### 解决方法（人手动，一步就好）
- **Windows（平台所在电脑）**：
  - 允许端口 8000（平台）+ 37020（UDP 发现）入站：
    ```powershell
    New-NetFirewallRule -DisplayName "edge-cluster" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
    New-NetFirewallRule -DisplayName "edge-cluster-discovery" -Direction Inbound -Protocol UDP -LocalPort 37020 -Action Allow
    ```
  - 或直接在「Windows Defender 防火墙 → 允许应用」里勾选 Python/uvicorn。
- **Android（手机）**：Termux 不需要入站端口（Agent 主动连平台），只需保活（见 Codex 指南 §5）。
- 若平台跑在 WSL：记得在 Windows 防火墙放行，且 WSL 与手机同网段（用电脑热点最稳）。

## §5 客户端隔离（校园网 / 公共热点）

### 根因（已实测踩过）
- 电脑连校园网、手机也连校园网 → 同网段被 AP 隔离，手机能打开平台网关页但 **WebSocket 注册失败**。
- 典型表现：控制台节点页看不到手机，Agent 日志无「平台确认注册成功」。

### 解决方法
1. **首选：电脑开移动热点，手机连这个热点**（已验证可行）。电脑热点侧 IP 如 `10.86.33.190`，手机 `10.86.33.31`，同网段可达。
2. **手动填 IP**：`phone_setup.sh --platform http://<电脑热点IP>:8000`，跳过 UDP 自动发现。
3. **关 AP 隔离**（若你有路由器管理权）：在路由器/交换机关掉「客户端隔离 / AP Isolation / 用户隔离」。
4. 不要用需要登录的 captive portal 网络（图书馆/宿舍公共网），它们几乎都隔离。

## 一句话总结
- **真做不到的只有一项**：CPU/GPU/NPU 真值，必须 root 或 Shizuku 给 Agent 提权（§1）。
- **其余都是「差一步」**：服务跑不起来 = 按指南接手机（§2）；网关限流/负载均衡 = 超出需求边界、建议在反向代理层做（§3）；防火墙 = 人放行（§4）；隔离 = 用电脑热点（§5）。
- 平台代码本身**没有卡死的硬伤**，所有「做不了」都落在系统权限或真人操作上。
