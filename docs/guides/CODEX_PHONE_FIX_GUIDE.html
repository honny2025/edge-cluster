手机端修复与补充指南（给 Codex）

这是一份自包含的执行指南。你（Codex）会被放进这部 Android 手机的 Termux shell 里，任务是：更新节点 Agent 代码、安装推理运行时 llama.cpp、配置保活、重启并验收。你不需要看任何聊天记录，照这份文档逐步执行，每一步把真实输出贴给人。

0. 一句话目标

把这部已经在线的手机，从「旧代码 + 没装推理运行时 + 会被息屏限速」修到「新代码 + llama.cpp 就绪 + 保活到位」，让人在平台上能稳定下发模型、拉起推理服务。

1. 现状（已知事实，不要重复确认）

事实说明
节点状态这部手机已经注册、在线，节点名 {{节点名}}。它是「更新 + 补充」，不是从零装。
平台地址http://{{平台IP}}:8000，health 接口无需鉴权。
共享 token{{TOKEN}}（通常已写在手机 config.toml 里，一般不用你动）。
旧代码的 bug旧 agent.py 断点续传会写坏文件（SHA 一直对不上、模型传过去用不了）；新包里已修。
服务起不来的原因手机还没装 llama-cli / llama-server（llama.cpp），所以「服务拉起」和「模型自检」都会失败。
下载慢/卡死的根因Android 息屏后的省电策略（Doze）把 Termux 后台网络限死。这不是代码或局域网问题，必须靠第 5 节的「保活」解决。

2. 任务总览（4 件事，按顺序做）

  1. 用新文件包覆盖 node-agent 代码（保留手机已有的 config.toml 和 state/）。
  2. 安装 llama.cpp，让 llama-cli 和 llama-server 都进 PATH。
  3. 配置保活（防息屏断流/被杀）—— 这是慢下载的根因。
  4. 重启 agent 并逐项验收。

3. Step 0 — 确认平台可达（拿不到就停）

curl -s --max-time 5 http://{{平台IP}}:8000/api/v1/system/health

期望看到包含 "status":"ok" 的 JSON。若超时/拒绝/不是 ok：停下，报告「平台不可达」，让人确认平台已启动、IP 没变、端口 8000 放行。不要继续往下走。

4. Step 1 — 覆盖 node-agent 代码（保留身份）

红线：绝不要覆盖或删除手机现有的 config.toml 和 state/ 目录。
config.toml 里有这部手机的真实 node_id / 名字 / 平台地址 / token；state/ 里有设备 token 和服务记录。一旦被冲掉，这部手机会以「新身份」上线，平台上旧节点掉线、下发任务失配。新包里故意不含 config.toml，就是防止整目录覆盖时误伤它。

4.1 定位现有的 node-agent

find /sdcard/Download /sdcard "$HOME" -maxdepth 5 -name agent.py 2>/dev/null | head -n 5

记下找到的目录（通常是 ~/node-agent 或 /sdcard/Download/node-agent）。找不到就停下报告，让人把新文件包 node-agent-2026-11-14.zip 传到手机。

4.2 备份身份文件（务必先做）

cd <node-agent目录>
cp -r config.toml state ~/node-agent-backup-$(date +%s) 2>/dev/null || cp config.toml ~/config.toml.bak
ls -la ~ | grep -E 'node-agent-backup|config.toml.bak'

目的是万一后面出错还能恢复身份。备份到 ~ 下，不要放在 node-agent 目录内（避免被覆盖）。

4.3 解压新包并覆盖（只覆盖代码，不碰身份）

cd ~
unzip -o /sdcard/Download/node-agent-2026-11-14.zip -d /tmp/pkg
# 只把代码文件拷进去；config.toml 本就不在包里，state/、logs/、models/ 不会被碰
cp -f /tmp/pkg/node-agent/*.py <node-agent目录>/
cp -f /tmp/pkg/node-agent/*.sh <node-agent目录>/
cp -f /tmp/pkg/node-agent/requirements.txt <node-agent目录>/ 2>/dev/null
rm -rf /tmp/pkg
注意：上面是「只覆盖 .py / .sh / requirements.txt」的安全做法。如果你用 unzip -o 直接解到 node-agent 目录，也行（因为包里没有 config.toml），但要确保解压后手机原来的 config.toml、state/、logs/、models/ 都还在。解压完用下一步的命令核对。

4.4 核对身份没被冲掉 + 新代码确实到位

cd <node-agent目录>
cat config.toml | grep -E '^(node_id|name|platform_url|token)'
grep -c '部署前清理上一轮残片' agent.py    # 期望输出 >= 1（新代码标记）
ls -la state 2>/dev/null && echo "state 目录还在"
  • config.toml 里 name 必须是 {{节点名}}、node_id 非空 —— 若不是，说明身份被冲了，立即用 4.2 的备份恢复。
  • grep -c '部署前清理上一轮残片' 输出 ≥1，说明新 agent.py 已生效。
  • state 目录还在，说明设备 token / 服务记录没丢。

5. Step 2 — 安装 llama.cpp（推理运行时）

模型自检默认用 llama-cli，模型服务用 llama-server。平台不负责装，必须手机自己装好。

5.1 先确认是否已装

command -v llama-cli llama-server 2>/dev/null || echo "未安装"

两个都输出路径 → 已装好，跳到 5.3。只有 main/server（llama.cpp 旧命名）→ 直接看 5.3 的命名兼容。

5.2 安装

pkg update -y && pkg install -y llama-cpp
command -v llama-cli llama-server 2>/dev/null || echo "仓库没有，走源码编译"

若没装上，源码编译（一定可行）：

pkg install -y git cmake ninja clang make
git clone --depth 1 https://github.com/ggml-org/llama.cpp.git ~/llama.cpp
cd ~/llama.cpp
cmake -B build -G Ninja -DGGML_NATIVE=OFF
cmake --build build -j4
ls build/bin/   # 看产物名：llama-cli/llama-server 或 main/server
手机上编译可能几分钟到几十分钟。若某 cmake 选项报错，以仓库 README 当前构建说明为准，别死磕。

5.3 放进 PATH + 旧版命名兼容（重要）

mkdir -p ~/bin
for b in llama-cli llama-server main server; do
  [ -f "$HOME/llama.cpp/build/bin/$b" ] && cp "$HOME/llama.cpp/build/bin/$b" "$HOME/bin/" && echo "copied $b"
done
# 若只有旧名字 main/server，用软链补齐新名字，平台默认命令就不用改
command -v llama-cli >/dev/null 2>&1 || ln -sf "$(command -v main)" ~/bin/llama-cli
command -v llama-server >/dev/null 2>&1 || ln -sf "$(command -v server)" ~/bin/llama-server
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
export PATH="$HOME/bin:$PATH"

目标：四个名字里至少 llama-cli 和 llama-server 都能被 command -v 找到。这样平台侧的「自检命令」「服务命令」无论用新名还是旧名都能跑。

5.4 验证

command -v llama-cli llama-server
llama-cli --version 2>&1 | head -1
echo "$PATH"

期望：前两条各打印一个路径 + 版本号（不是 command not found / 空）。没成功就停在原地，报告卡在哪一步、什么报错，不要伪造「已装好」。

6. Step 3 — 保活三件套（防息屏断流/被杀，关键）

这是「模型下载慢到离谱/卡死」的根因。不关掉 Android 的省电策略，新代码和 llama 都白装：息屏几分钟后 Termux 后台网络被限速、进程被冻结甚至被杀，几个 GB 的模型永远下不完。分「你能做」和「必须人做」两部分。

6.1 你能做（Termux 内）

# 唤醒锁：装了 Termux:API 才有用
pkg install -y termux-api 2>/dev/null
command -v termux-wake-lock >/dev/null 2>&1 && termux-wake-lock && echo "唤醒锁已开" || echo "termux-wake-lock 不可用，需转告人装 Termux:API 应用"

6.2 必须转告「人」手动做（Codex 碰不到 GUI）

位置动作
设置 → 应用 → Termux → 省电策略改为「无限制 / 允许后台活动」
设置 → 应用 → Termux打开「允许自启动」
最近任务列表 → Termux 卡片下拉加锁（防一键清理误杀）
荣耀 / MagicOS 额外设置 → 应用 → 应用启动管理 → Termux → 关「自动管理」，手动全开三个开关
（可选但推荐）下载模型期间让手机保持亮屏、插电，进一步避免息屏限速

这步做完，把结果（是否已逐项开启）如实写进报告。

7. Step 4 — 重启 agent 并验收

7.1 停掉旧 agent，确认死透

pkill -f agent.py
sleep 2
pgrep -f agent.py || echo "旧进程已停止"

若 pgrep 仍有输出，再 pkill -9 -f agent.py 直到输出为空。

7.2 启动新 agent

cd <node-agent目录>
nohup python3 agent.py >> logs/nohup.log 2>&1 &
sleep 6
pgrep -f agent.py   # 期望输出一个 PID

7.3 验证注册成功

tail -n 30 <node-agent目录>/logs/<节点名>.log

期望出现「平台确认注册成功」。同时让人在电脑控制台节点页确认 {{节点名}} 仍然在线（且是同一个节点，不是新冒出来的）。

8. 验收标准（全部满足，缺一条报告失败原因）

  • ☐ grep -c '部署前清理上一轮残片' agent.py 输出 ≥ 1（新代码已生效）
  • ☐ config.toml 里 name 是 {{节点名}}、node_id 非空，state/ 目录还在（身份未丢）
  • ☐ command -v llama-cli llama-server 各打印一个路径
  • ☐ termux-wake-lock 已执行（或已明确报告「不可用，需人装 Termux:API」）
  • ☐ 第 6.2 节的人手动设置已逐项转告并确认
  • ☐ pgrep -f agent.py 输出一个 PID
  • ☐ 日志出现「平台确认注册成功」
  • ☐ 电脑控制台节点页能看到 {{节点名}} 且在线

10. 约束（务必遵守）

  • 不要修改任何 .py 的逻辑、不要覆盖 config.toml / state/。
  • 不要为了验收通过而伪造日志、假造输出或跳过失败步骤。
  • 失败时最多重试 2 次，之后停在原地报告真实原因和完整日志。
  • 每一步的真实输出都要给人，不要只说「已完成」。

附 A — 给「人」（平台侧）的两点提醒（不在 Codex 手机任务内）

  • 模型「自检命令」要用 {model_path} 占位符，例如：llama-cli -m {model_path} -p hi -n 4。Agent 会把 {model_path} 替换成手机上真实的落盘路径，不要写死路径。
  • 创建「服务」时，-m 指向的模型路径是手机上的真实路径，形如 ~/node-agent/models/<模型文件名>.gguf（Agent 会把模型下到 models 目录）。命令名用 llama-server（或与手机二进制一致的名字，第 5.3 节已保证新旧名都可用）。
