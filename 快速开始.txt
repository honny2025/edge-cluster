======================================================================
 手机边缘计算集群管理平台 · 快速开始
======================================================================

这个文件夹就是完整的系统。不需要安装，复制走就能跑。


----------------------------------------------------------------------
 Windows：三步跑起来
----------------------------------------------------------------------

   1) 双击  启动.bat
      （推荐方式，它自动绕过 PowerShell 的脚本执行限制）

   2) 等它跑完（首次会创建虚拟环境并装依赖，一两分钟）

   3) 浏览器打开  http://127.0.0.1:8000

   停止：双击  停止.bat


 想用命令行而不是双击的话，两种写法都可以：

   .\start_all.ps1                                          # 可能被拦，见下方
   powershell -ExecutionPolicy Bypass -File .\start_all.ps1  # 一定可以

   可选参数：
   .\start_all.ps1 -Nodes 5           # 起 5 个模拟节点
   .\start_all.ps1 -NoNodes           # 只起平台
   .\start_all.ps1 -DevWeb            # 额外起前端开发服务器（改前端用）
   .\start_all.ps1 -Port 8001         # 换平台端口（模拟节点会自动跟着换）


----------------------------------------------------------------------
 Linux / macOS
----------------------------------------------------------------------

   1) bash start_all.sh

   2) 浏览器打开  http://127.0.0.1:8000

   停止：bash stop_all.sh

   注意：zip 不保留 Unix 可执行权限，所以上面用的是 "bash start_all.sh"
   而不是 "./start_all.sh"。想用 ./ 方式的话先执行：
       chmod +x start_all.sh stop_all.sh


----------------------------------------------------------------------
 运行前需要装什么
----------------------------------------------------------------------

必需：Python 3.10 或更高版本
可选：Node.js 18+（仅当你需要修改前端代码时）

   本包已包含构建好的控制台（web/dist），所以不改前端就用不到 Node。
   一键脚本会自动创建虚拟环境并安装依赖，不会污染你的系统环境。

Python 不在默认位置时，可以用环境变量指定：

   $env:EDGE_PYTHON = "D:\Python311\python.exe"
   powershell -ExecutionPolicy Bypass -File .\start_all.ps1

   （同理 EDGE_NODE 可指定 Node 所在目录）

一键脚本首次运行时会做的事：

   * 自动探测可用的 Python，并校验版本 >= 3.10（不达标会明确告诉你差在哪）
   * 在项目内创建 .venv 并安装依赖；默认源装不动时自动改用清华镜像重试
   * 启动前检查端口占用，被占用会提示你换端口，而不是等半天说一句"未就绪"
   * 不写任何系统目录、不改注册表 —— 卸载就等于删掉这个文件夹


----------------------------------------------------------------------
 端口 8000 被占用 / 想换端口
----------------------------------------------------------------------

   .\start_all.ps1 -Port 8001

   模拟节点会自动连到新端口，不需要改任何配置文件。

   如果脚本提示"端口已被占用，平台起不来"，但平台其实已经在跑，
   那直接打开 http://127.0.0.1:8000 就行（换过端口就用你换的那个），不用再启动一次。


----------------------------------------------------------------------
 ★ 如果提示"禁止运行脚本" / "无法加载文件 xxx.ps1"
----------------------------------------------------------------------

这是 Windows 的 PowerShell 默认安全策略，不是你装的系统有问题。
报错长这样：

   无法加载文件 ...\start_all.ps1，因为在此系统上禁止运行脚本。

三种解法，任选一种：

   ① 直接双击 启动.bat          <- 最省事，推荐
   ② 用完整命令启动：
        powershell -ExecutionPolicy Bypass -File .\start_all.ps1
   ③ 一次性放开当前用户的脚本权限：
        Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
      之后 .\start_all.ps1 就能直接跑了。

   （补充：在某些自动化/非交互环境里，脚本被拦时是"静默失败"——不报错
     也不执行。如果发现什么都没发生，直接用方式 ① 或 ②。）

 跑起来会看到什么

这是模拟数据，用来确认系统运行正常，不需要任何真机。

----------------------------------------------------------------------
 这个包不包含什么（故意的）
----------------------------------------------------------------------

node_modules/      前端依赖，体积 260MB 且与平台相关，npm install 会重建
.venv/             Python 虚拟环境，一键脚本会自动创建
server/data/       SQLite 数据库（原机器的节点记录与历史指标）
node-agent/state/  节点身份文件（node_id）——外传会造成身份冲突
node-agent/logs/   原机器的运行日志

这些都属于"原机器的运行状态"，不是代码的一部分。

 重新打包（改了代码之后）
----------------------------------------------------------------------

会读代码里的版本号，生成 edge-cluster-portable-<版本>.zip，
并自检包内不含 node_modules / 数据库 / 节点身份 / 日志。


----------------------------------------------------------------------
 ★ 升级时不要"覆盖解压"（实测会丢文件）
----------------------------------------------------------------------

   PowerShell 的 Expand-Archive 加 -Force、或解压到一个**已存在的**目录，
   会先把目标目录清干净、然后又不写文件 —— 而且**不报错**。

   实测：同一个 zip 解压两次，第二次之后目录里的文件从 85 个变成 0 个。

   正确做法（任选一种）：

     ① 解压到一个**新文件夹**，然后把旧的这两处拷过去，再删掉旧文件夹
          server\data\        平台数据库（节点列表 + 历史指标）
          node-agent\state\   节点身份文件（拷走可保持 node_id 不变）

     ② 确认不需要旧数据后，直接删掉旧文件夹，再解压一次

   注意别把上面那两个目录当垃圾丢掉，它们不在 zip 里。
   （用 7-Zip 之类逐文件解压的工具一般不会触发这个问题，但仍建议按上面做。）
