# 手机边缘计算平台：工作室局域网实施步骤

本文假设：一台 Windows 电脑作为平台主机，两部 Android 手机作为节点。所有设备连接同一个工作室 Wi‑Fi。

## 1. 准备设备

需要：

- Windows 10/11 电脑一台
- Android 手机两部
- 同一个工作室路由器/Wi‑Fi
- 手机可以安装 Termux

不要使用访客 Wi‑Fi。工作室路由器需要关闭“AP 隔离/无线客户端隔离”。

## 2. 解压和检查平台

将 `edge-cluster` 文件夹复制到电脑，例如：

```text
D:\edge-cluster
```

打开 PowerShell，执行：

```powershell
cd D:\edge-cluster
python --version
```

必须显示 Python 3.10 或更高版本。

如果没有 Python，从 python.org 安装 Python 3.10+，安装时勾选“Add Python to PATH”。

## 3. 获取电脑局域网 IP

在 PowerShell 执行：

```powershell
ipconfig
```

找到当前 Wi‑Fi 网卡的 IPv4 地址，例如：

```text
IPv4 Address . . . . . . . . . . : 192.168.50.10
```

本文后续把它记为 `<平台IP>`。实际操作时必须替换成真实地址。

## 4. 放行 Windows 防火墙

使用“管理员 PowerShell”执行：

```powershell
New-NetFirewallRule -DisplayName "EdgeCluster HTTP 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
New-NetFirewallRule -DisplayName "EdgeCluster Discovery 37020" -Direction Inbound -Protocol UDP -LocalPort 37020 -Action Allow
```

执行后不应出现红色错误。

## 5. 启动平台

在普通 PowerShell 执行：

```powershell
cd D:\edge-cluster
启动.bat
```

保持这个窗口不要关闭。看到服务监听 `8000` 后，在电脑浏览器打开：

```text
http://127.0.0.1:8000
```

手机访问时使用电脑局域网 IP：

```text
http://192.168.50.10:8000
```

接口文档地址：

```text
http://192.168.50.10:8000/docs
```

## 6. 在第一部手机安装 Agent

在手机安装 Termux。建议从 F-Droid 安装，不要混用 Google Play 旧版本。

打开 Termux，执行：

```bash
pkg update -y
pkg install python openssh rsync -y
```

把电脑上的 `node-agent` 文件夹复制到手机。最简单的方式是使用 USB，复制到手机内部存储后执行：

```bash
termux-setup-storage
cp -r /sdcard/node-agent ~/node-agent
cd ~/node-agent
pip install -r requirements.txt
```

让第一部手机连接平台：

```bash
python agent.py --name studio-phone-01 --platform-url http://192.168.50.10:8000
```

把命令中的 IP 换成第 3 步查到的真实平台 IP。保持 Termux 窗口运行。

## 7. 在第二部手机安装 Agent

重复第 6 步，但节点名称必须不同：

```bash
python agent.py --name studio-phone-02 --platform-url http://192.168.50.10:8000
```

不能两部手机都使用同一个 `--name`，否则平台会把它们识别成同一个节点。

## 8. 确认节点在线

电脑浏览器打开：

```text
http://192.168.50.10:8000
```

进入“节点管理”，应看到：

- `studio-phone-01`：在线
- `studio-phone-02`：在线
- 两台设备的 IP、CPU、内存、存储和温度

如果 30 秒后仍没有节点，依次检查：

1. 手机浏览器能否打开 `http://192.168.50.10:8000`。
2. 电脑和手机是否连接同一个 Wi‑Fi。
3. Windows 防火墙是否放行 8000 端口。
4. Agent 命令中的 IP 是否写成了电脑真实局域网 IP。
5. 路由器是否开启 AP 隔离。

## 9. 验证断线重连

在第一部手机关闭 Wi‑Fi，等待 20–30 秒。平台节点状态应变为“离线”。

重新打开 Wi‑Fi，等待 10–20 秒。状态应自动恢复为“在线”。

如果没有恢复，回到手机 Termux 窗口确认 Agent 进程仍在运行。

## 10. 迁移到工作室电脑

迁移前在旧电脑执行：

```powershell
cd D:\edge-cluster
启动.bat
```

先关闭平台，再完整复制以下目录到移动硬盘或 U 盘：

```text
edge-cluster\server\data
edge-cluster\server\config.toml
edge-cluster\node-agent
edge-cluster\web
启动.bat
```

在工作室电脑建立目录，例如：

```text
D:\studio-edge-cluster
```

将上述内容复制进去。然后在工作室电脑执行第 2、3、4、5 步。

工作室电脑 IP 变化后，两部手机重新执行：

```bash
cd ~/node-agent
bash install.sh --token 你的平台token --platform http://新的平台IP:8000 --name studio-phone-01
```

第二部手机把 `--name` 换成 `studio-phone-02` 再跑一次。

> 节点名称**不要改**，否则平台会当成新节点，原来的历史指标就对不上了。
> 用 `install.sh` 而不是直接 `python agent.py`：它会顺带写好 token、申请存储权限和唤醒锁、
> 装开机自启 —— 漏掉任何一步，息屏十分钟后就会掉线。

## 11. 迁移后验证数据

迁移完成后检查：

1. 浏览器能打开平台首页。
2. `http://新的平台IP:8000/docs` 能打开接口文档。
3. 节点管理能看到两部手机。
4. 原来的模型记录仍在。
5. 原来的部署任务和服务记录仍在。
6. 手机停止和恢复网络后，在线状态正常变化。

## 12. 真机测试顺序

按以下顺序测试，不要一开始就部署大模型：

**第一段：接入与监控（这一步稳了再往下走）**

1. 平台首页打开，右上角版本号与 `curl .../api/v1/system/health` 的 `version` 一致。
2. 第一部手机在线，型号 / SoC / Android / IP 与 `getprop` 对得上。
3. 第二部手机在线（**节点名必须不同**）。
4. 断网、恢复和自动重连：断网 20~30 秒平台转离线，恢复 10~20 秒转在线。
5. 节点详情页看历史曲线；CPU 显示 `—` 属正常（见 `真机测试检查单.md` 第 0 节）。

**第二段：模型下发与服务（用小模型先跑通）**

6. 模型页上传一个轻量 ONNX/OCR 模型 → 看 sha256 校验与断点续传是否正常。
7. 下发到 1 台手机 → 任务页应看到逐秒真实进度；完成后自动做一次 Self Test。
8. 服务页新建服务 → 启动 → 状态收敛到 `running`。
9. 平台探活通过后，用网关调用 Endpoint（OpenAI 兼容请求按原样透传），首页看请求量与延迟。
10. 杀掉 Agent 再重启 → 配了 `auto_start` 的服务应自己回来。

**第三段：确认能跑通之后再上大模型**

11. 部署 LLM 模型，重复 7~10 步。

**边角功能**：文件页可在白名单沙箱内浏览手机文件并双向传输；审计页能看到上面所有写操作的留痕。

> 平台负责分发、拉起、探活和统计 —— 但**平台不懂模型**。具体跑 llama.cpp 还是 ONNX Runtime、
> 用什么参数，需要在服务定义里填。模型的实际运行还取决于手机端装了什么推理运行时；
> GPU/NPU 指标也要按厂商单独适配，不暴露 sysfs 节点的机型拿不到值。
