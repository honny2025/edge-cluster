先看这一段（30 秒读懂怎么用这份指南）：这份指南是给你照着做的，按顺序走，每做完一步都有「怎么算成功」的判断标准， 不需要你懂代码。下面所有 【平台IP】 都要换成你电脑的真实局域网 IP（阶段 0 会教你查）， 所有 【节点名】 换成每部手机各自的名字。
全程手动操作，手机不装任何 AI 助手。这份指南的每一步都是你自己在手机上一条条敲命令， 不需要在手机上装 Codex / Claude 这类「智能体」，也不需要联网下载任何 AI 工具。 手机上只装一个东西 —— Termux（一个普通的 Linux 终端，不是 AI）， 然后把平台自带的 node-agent 代码拷进去、跑一条安装命令。 （install.sh 是平台自带的普通脚本，会自动帮你装依赖、写配置，但它不是 AI，也不用你额外装什么。）
四件最容易被坑的事，提前说： ① 工作室的路由器很可能开了「AP 隔离」，手机和电脑互相看不见 —— 阶段 0 有 5 分钟就能绕过的办法； ② 手机息屏 10 分钟必掉线，除非做完「保活设置」（阶段 1 的最后一步，必须手动点系统设置）； ③ 平台里 CPU / 负载 / 网络流量显示 — 是正常的，不是坏了（Android 的安全机制封了这些接口，拿不到就诚实留空）； ④ 手机的中文输入法会把 -- 变成全角横杠，导致 install.sh 报「未知参数」。所以名字别在手机上敲 —— 见阶段 1.3 的「不带 --name」写法，连上后去平台网页改名即可（改完永久生效）。

备出发前：把 APK 和代码先备好

工作室里的手机都没装 Termux，而且现场网络不一定能顺畅下载。所以出发前在家里先把下面三样东西下好、传好，现场就不用抓瞎。

① 下载这三个 APK（放到 U 盘或先发到手机）

手机都要先装 Termux（手机上的 Linux 终端，Agent 跑在它里面）。从 F-Droid 官方下，别用 Google Play 的老版本：

  • Termux —— 必装。下载页：https://f-droid.org/packages/com.termux/
  • Termux:API —— 可选，装了才能读到手机的电量/温度。下载页：https://f-droid.org/packages/com.termux.api/
  • Termux:Boot —— 可选，装了才能开机自启。下载页：https://f-droid.org/packages/com.termux.boot/
嫌麻烦的话，只下 Termux 一个也能跑通主线，只是平台上「温度/电量」会显示 —（不算失败）。
怎么判断装到了旧版：打开 Termux 跑 termux-setup-storage 如果不弹「允许访问文件」的系统框、或家目录里没有 storage 文件夹，就是 Google Play 的 2020 旧版，在 Android 11+ 上已坏 —— 卸载后从 F-Droid 重装即可。

② 把 node-agent 打包好

从安装包解压出来的 edge-cluster 目录里，把 node-agent 这个文件夹压成 node-agent.zip， 用数据线（最稳）或 QQ/微信传到每部手机的 Download 目录。手机上只认这一个文件夹，别的都不用拷。

压缩前必须先删掉两个目录，否则手机一定连不上（踩坑记录 #9，实测踩过）： node-agent/state/ 和 node-agent/logs/。

原因：电脑上跑过模拟节点（phone-01/phone-02）之后，state/ 里会留下开发机的 旧身份和旧设备 token（by-name-phone-02.json、token-phone-02-9885af5d.json）。 这个包一发到手机，Agent 就会拿别的平台签发的旧 token 去握手，被平台拒掉，形成 HTTP 403 无限重连。logs/ 里还会带着开发机的 Windows 路径（E:\Users\<用户名>\...），看着也容易误判。

一句话：手机要的是一份「干净代码」。打包前 rm -rf node-agent/state node-agent/logs（Windows 上右键删掉这两个文件夹）再压缩。

已经打到一半、包里带着 state/ 也不要紧 —— 阶段 1.2 有一步「到了手机再清一遍」，照样能救。

③ 出发清单（照这个勾）

  • 电脑一台（带电源，建议插网线更稳）
  • 安装包 zip（或已经把 edge-cluster 解压好、能在电脑上跑起来）
  • 几部测试手机 + 数据线（传文件用）
  • 上面 ① 的三个 APK（U 盘或已发到手机）
  • 电脑上确认有 Rust 工具链（cargo） —— 首次启动平台会自动 cargo build --release 编译 Rust 二进制（联网下载 crates 依赖，首次几分钟，之后秒起）；没装就从 rustup.rs 装，或带好能离线编译的二进制
  • 每部手机最好能上网 —— 过渡期 install.sh 要联网装 Python 依赖；要做第三段还得能 pkg install llama-cpp
  • （可选）想做第三段的手机，提前在 Termux 里跑一遍 pkg install -y llama-cpp && command -v llama-cli llama-server， 别把「现场装推理引擎」留到验收当天 —— 万一某个机型源里没有、只能走 pip 编译，那是几十分钟起步

0电脑就位，平台跑起来

目标：电脑上打开 http://127.0.0.1:8000 能看到平台，右上角版本号 v0.5.0-m5，节点数是 0。

0.1 解压并确认 Rust 工具链

把安装包解压到一个不带中文的路径（例如 D:\edge-cluster）。在项目目录里打开 PowerShell，确认 Rust 工具链：

cargo --version

有版本号输出就行（本工程用 1.99.0 编译验证过）。没有就去 rustup.rs 装（选默认的 GNU 工具链；若用 MSVC 工具链则无需额外配置，GNU 工具链需要 MinGW 链接器在 PATH 上）。

0.2 拿到电脑的局域网 IP

这是后面所有 【平台IP】 的来源。在 PowerShell 执行：

ipconfig | Select-String "IPv4"

找你正在上网的那块网卡（WLAN 无线 或 以太网）的 IPv4 地址，例如 192.168.1.100，记下来。

别拿错：排除 127.0.0.1、169.254.x.x（没拿到 IP），以及 VMware / VirtualBox / 手机 USB 共享网络那几块虚拟网卡的 IP。

0.3 放行 Windows 防火墙（需要管理员权限）

右键开始菜单 → Windows PowerShell（管理员） → 粘贴这两行回车：

New-NetFirewallRule -DisplayName "EdgeCluster HTTP 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
New-NetFirewallRule -DisplayName "EdgeCluster Discovery 37020" -Direction Inbound -Protocol UDP -LocalPort 37020 -Action Allow

不出现红色报错（会回显一行规则信息）即成功。

0.4 启动平台（只起平台，不起假节点）

在普通 PowerShell 里，进入项目目录执行下面这条。它第一次会自动 cargo build --release 编译 Rust 二进制（联网下载 crates，几分钟），之后就秒起。

powershell -ExecutionPolicy Bypass -File .\start_all.ps1 -NoNodes

-NoNodes 是不要模拟节点。不加的话会启动 2 个叫 phone-01 / phone-02 的假节点，容易和真机搞混。

看到 启动完成 后，浏览器打开 http://127.0.0.1:8000：右上角 v0.5.0-m5，节点页没有节点，就是对的。

双击 启动.bat 也能启动，但那个会顺带起 2 个假节点。真机测试建议就用上面这条命令。

0.5 用手机浏览器先探路（能省你半小时）

随便拿一部手机，连上和电脑同一个 Wi-Fi，用系统自带浏览器打开：

http://【平台IP】:8000/api/v1/system/health

看到 {"status":"ok",...} 就说明网络通了，直接进阶段 1。

打不开？按顺序排查：① 手机是不是连错网络了（光猫 Wi-Fi 和路由器 Wi-Fi 是两个网段）；② 手机能不能打开路由器管理页（如 http://192.168.1.1）；③ 路由器页打得开、平台打不开 → 就是「AP 隔离」，工作室网络几乎必开。绕过办法看下面。

绕过 AP 隔离（5 分钟，100% 有效）：让手机连电脑开的热点

  1. 电脑：设置 → 网络和 Internet → 移动热点 → 打开（共享来源选「WLAN」）。
  2. 手机：连上这个热点（关掉原来的 Wi-Fi）。
  3. 电脑重新执行 ipconfig | Select-String "IPv4"，取 WLAN 网卡的新 IP —— 这就是新的 【平台IP】。
  4. 手机重新打开 http://【新平台IP】:8000/api/v1/system/health。
平台监听的是 0.0.0.0（所有网卡），换网络不用重启平台。电脑开热点失败的话，反过来：手机开热点、电脑连上去，再用电脑的新 IP 访问。
别用 ping 判断通不通：Windows 防火墙默认禁 ICMP，手机 ping 不通电脑不代表 8000 端口不通。只认浏览器能不能打开那个地址。也别用 UC / 夸克这类带「云加速」的浏览器，它们会把内网请求走云端，必然打不开。

1第一部手机接入（先跑通 1 部，再加别的）

每部手机约 15 分钟（首次装依赖偏慢）。先只装 1 部，确认整条链路通了，再复制到其余手机。

为什么手机端还是 Python：后端已经整体 Rust 重写，但手机端的 Rust Agent（node-agent-rust/）还没出 aarch64 真机二进制、没真机验证， 所以过渡期手机仍跑 Python Agent（install.sh + agent.py），与电脑上的 Rust 平台靠不变的 wire 协议互通 —— 本阶段所有步骤照旧有效。

1.1 装 Termux

  1. 把出发前下好的 Termux APK 装到手机上（首次装陌生来源应用，系统会要求你「允许安装未知应用」，点允许）。
  2. 可选：再装 Termux:API（读电量/温度）和 Termux:Boot（开机自启）。
  3. 打开 Termux，更新包源：
pkg update -y && pkg upgrade -y

1.2 把 Agent 代码拷进 Termux

先把出发前打包的 node-agent.zip 用数据线传到手机 Download（或 QQ 文件助手），然后：

termux-setup-storage
# 上面会弹系统权限框，点「允许」
find /sdcard/Download -maxdepth 4 -name "agent.py" 2>/dev/null

上面这条是问出来代码在哪。把输出那一行去掉末尾的 /agent.py，就是目录路径（例如 /sdcard/Download/node-agent），填进下面的 【目录】：

cp -r 【目录】 ~/node-agent
cd ~/node-agent && ls

应该能看到 agent.py、install.sh、config.toml、agent_metrics.py 等文件。

拷完先做一件事：清掉包里可能残留的旧身份（30 秒，能省你半小时）。 
ls -la ~/node-agent/state/ 2>/dev/null
# 如果看到 by-name-*.json / by-id-*.json / token-*.json —— 说明是开发机的残留，清掉：
rm -rf ~/node-agent/state/* ~/node-agent/logs/*
不清理的症状：Agent 能跑起来，但日志里反复出现 连接中断: server rejected WebSocket connection: HTTP 403，平台「节点」页死活看不到这台手机（踩坑记录 #9）。 正常情况 state/ 应该是空的或不存在，第一次启动后 Agent 自己会生成自己的身份。
两个坑：① 必须拷进 ~（Termux 的家目录），别在 /sdcard 原地跑 —— 共享存储没有 Linux 权限位，会出各种怪问题；② 如果传的是 .zip，先在 Termux 里 pkg install unzip && cd /sdcard/Download && unzip node-agent.zip 再继续。
代码必须用电脑上最新那份，别用以前留下的旧包。手机里若是旧版 agent（0.1.0-m1），模型下发会秒失败 401（踩坑记录 #8）。传之前先确认电脑 node-agent 目录里 agent_config.py 写着 AGENT_VERSION = "0.5.0-m5"；传完手机日志里出现 version=0.5.0-m5 才算数。

1.3 一键安装并接入平台（名字别在手机上敲）

这是实测翻车最多的一步：--name 别在手机上敲。 手机中文输入法会把 --name 里的两个减号变成全角横杠，脚本只认 ASCII 减号， 于是报 未知参数: --name。所以这条命令不带名字，名字等连上后去电脑网页改（阶段 3）： 
cd ~/node-agent
bash install.sh --platform http://【平台IP】:8000

说明：

  • --name 省略 —— 名字去网页改，改完永久生效（手机端上报不会覆盖）。
  • --token 省略 —— config.toml 里默认就是 edge-cluster-dev-token，不用传。

  • --platform 保留 —— 显式指定平台最稳。若手机和电脑同网段且 UDP 广播正常，也能省成 bash install.sh，但显式写更保险。

它会自动：装 python 和依赖 → 写平台地址 → 申请存储权限和唤醒锁 → 写保活脚本 → 装开机自启 → 启动 Agent → 打印最近日志。

第二段：模型下发与服务托管（直接用真模型 Qwen3-1.7B，1.1GB）

先看这条 —— 实测最贵的一个坑：模型「部署成功」不等于模型「能用」（踩坑记录 #18）。

现象：模型上传入库成功 → 下发进度条走完 → 节点状态「就绪」→ 手机上 sha256sum 和平台一模一样。 一路全绿，但模型吐出来的字是乱码 + 复读（`我 myselfservetetetetete…`、`mememememememe…`）。

根因：上传到平台的那个文件本身就是坏的 —— 实测发现平台上的副本从第 883,032,065 字节起 全是 0x00，也就是最后约 224MB 权重被零填充（上传时截断，但文件大小被补足到正确值）。 因为 sha256 是"坏文件自己算出来的"，平台登记的、手机上落盘的、你比对的三方当然全都一致 —— T12 查不出这种错。

所以 T12 必须升级成两步：① 平台 sha == 手机 sha（原有）；② 平台 sha == 来源文件/官方发布的 sha（新增，这才是关键）。

怎么快速确认来源文件没坏：看尾部有没有大段零 —— tail -c 64 模型.gguf | od -An -tx1；或直接和官方 sha 比： sha256sum 模型.gguf，Qwen3-1.7B Q4_K_M（unsloth 版）是 b139949c5bd74937ad8ed8c8cf3d9ffb1e99c866c823204dc42c0d91fa181897。 两个同来源文件也可以用 cmp -l 文件A 文件B | head 看第一个差异字节在哪。

桌面上已经有一个真模型：Qwen3-1.7B-GGUF/Qwen3-1.7B-Q4_K_M.gguf（约 1.1GB，llama.cpp 的 GGUF 格式，量化 Q4_K_M）。这一整段拿它验「大文件能否完整送到手机」。上传模型时表单这样填：

Self Test 命令留空（跳过自检直接「就绪」；手机还没装 llama.cpp，填了反而会失败）

部署页（新建部署任务）：模型选 qwen3-1.7b (v1) · Q4_K_M，目标节点勾那台手机，备注随意。预检会自动跑 —— 因为上面全留空，结论是「全部未登记 → 放行」。点「创建并下发」后，1.1GB 通过 Wi-Fi 传到手机，需要几分钟，进度条逐秒推进 实测：手机→平台走 Wi-Fi 约 16 MB/s，1.1GB 约 70 秒。
「创建并下发」点一次就够了 —— 别在任务已经跑起来之后再点一遍「开始」（踩坑记录 #10，实测踩过）。

实测发现：用 API 先建任务、再调一次「开始」，平台会把同一条 deploy_model 指令给同一台手机下发两次 （服务端日志里能看到同一个 task_id 连着两条「已下发」）。手机不会去重（它只按 cmd_id 去重，两次的 cmd_id 不同）， 结果就是老老实实再下 1.1GB，白等一分多钟、白费流量，还会在手机 models/ 里留下一个 .part 残留文件。

网页上正常点一次「创建并下发」不会触发这个问题。万一怀疑重复下发了： tail -f ~/node-agent/logs/【节点名】.log 看不到部署过程（成功部署不打日志）， 直接看手机 ls -la ~/node-agent/models/ 有没有正在变大的 .part 最直观。

关于手机上的 .part（实测补充，踩坑记录 #12）：Agent 下载模型是「先写 模型名.gguf.part → 校验 sha256 → 原子改名成最终文件」。正常情况下你看不到它，看到就说明上次下载没走完。
  • 好处：.part 比目标文件小的时候，下次下发会断点续传，不重头来（实测：预置 500 MB 的 .part，重新下发时进度直接从 52% 起步）。
  • 坑：.part 正好等于目标大小时，续传会发出 Range: bytes=<全长>-，平台回 HTTP 416: Range Not Satisfiable，部署直接失败（这次失败发生在改动设备文件之前，模型本身没坏）。
  • 怎么处理：看到 deployments 里报 416，先在手机 ls -la ~/node-agent/models/， 把那个 .part 删掉（rm ~/node-agent/models/*.part）再重新下发即可。
所有写操作都会在「审计」页留痕 —— 测完可以去审计页看一遍，这也是要验的功能之一。

第三段（可选）：真把 Qwen 跑起来（手机要自己装推理引擎）

平台只负责把模型文件发到手机，不负责推理，也不会替你在手机上装推理引擎。 install.sh 只装了 websockets / httpx 两个 Python 依赖，没有 llama.cpp。 要让 Qwen 真正吐出字，得先在手机上装 GGUF 的推理运行时（llama.cpp），再用「服务」把它拉起来。

3a. 手机上装 llama.cpp

pkg install -y llama-cpp

Termux 官方源里是有 llama-cpp 的（实测装到的是 0.6.0，同时提供 llama-cli 和 llama-server）。 万一这个包没了，退路是 pip install llama-cpp-python（要现场编译，很慢，别在验收当天现装）。

关键更正：llama-cli 不是 HTTP 服务，用它做服务的话网关调不通。
  • llama-cli = 手机本地敲命令、交互式聊天，不监听端口。它只适合「验证模型和引擎能不能跑」，也就是下面 3a′。
  • llama-server = 监听端口、提供 OpenAI 兼容的 /v1/chat/completions。要连平台网关（T18）必须用它。
（原稿的 3b 写的是 llama-cli + 端口 8080，这两个凑不到一起，已按实测改正。顺带：-no-cnv 这个参数在当前 0.6.0 上会报 invalid argument，别写。）

3a′. 先在手机上裸跑一次（确认引擎和模型都好使）

  -p "用一句话介绍你自己" -n 48 -t 6

能看到它打印模型信息、并一个字一个字往外吐，就算成功。实测（这台机） Qwen3-1.7B Q4_K_M 在这台 MTN-AN80 上：生成约 8 tokens/s，prompt 处理约 1.2 t/s。 注意 Qwen3 是「会先想再答」的模型，-n 48 这种很短的长度往往还没想完就被截断，输出看着像胡话是正常的，不代表模型坏了 —— 想看正经回答把 -n 放到 256 以上。

三个坑（务必看）： ① 服务「启动命令」里的 {model_path} 占位符不生效（只有模型的「Self Test」支持它），必须写手机上的绝对路径； ② 命令不经 shell 执行，~ 波浪号不会被展开，所以别写 ~/node-agent/…，要写 /data/data/com.termux/files/home/node-agent/…； ③ 若你的 node-agent 不是拷在 ~/node-agent，先在手机跑 ls ~/node-agent/models/ 确认真实文件名，路径按实际情况改。
④ 服务启动即崩溃、日志只有一行 CANNOT LINK EXECUTABLE "llama-server": cannot locate symbol "_ZNSt6__ndk113__hash_memoryEPKvm" ...： 这不是模型问题，是手机的动态库搜索路径被污染了。

本机实测到的原因（★仅限这台手机，不是通用结论★）：这台手机装了 @mmmbuto/codex-cli-termux 这个 npm 包， 它会在终端环境里注入 LD_LIBRARY_PATH=/data/data/com.termux/files/usr/lib/node_modules/@mmmbuto/codex-cli-termux/bin， 而这个目录里带着一份旧版 libc++_shared.so（缺 __hash_memory 符号）。 LD_LIBRARY_PATH 的优先级高于程序自带的 RUNPATH，于是 llama-cli / llama-server 加载了错误的 libc++， 一启动就死。更坑的是：Agent 会把继承到的环境原样传给托管服务，所以从这种终端启动的 Agent， 它拉起的每个 C++ 服务都会跟着崩（实测服务日志里连崩 6 次、状态显示 crashed）。

通用排查顺序（任何手机都适用）：

  1. 先看是不是路径污染的锅：env | grep LD_LIBRARY_PATH。有输出就先清掉再试 （env -u LD_LIBRARY_PATH llama-server --version 能跑就是这个问题）。
  2. 确认后，用干净环境启动 Agent（不然托管服务还是会被污染）： 
    pkill -f '^python3 agent.py$'
cd ~/node-agent && env -u LD_LIBRARY_PATH setsid nohup python3 agent.py >> logs/nohup.log 2>&1 < /dev/null &
  3. 没有 LD_LIBRARY_PATH 还是报同样的错，才轮到「库版本对不上」：pkg update && pkg upgrade && pkg install --reinstall llama-cpp libc++。
  4. 还是不行，就别在这个手机上硬啃 llama.cpp，改用 pip install llama-cpp-python 或换一台手机 —— 这一段的验收重点是「平台能托管、能通过网关调到」，不是「必须用某个引擎」。

给后续多机部署的提醒：这个问题只在这台装了 codex CLI 的手机上出现，别的手机如果没装那个包，很可能一次就过。 但反过来也成立 —— 在这台机上「一次就过」的经验，不能直接套到别的手机上：推理引擎装没装、能不能装、GPU 能不能读到、 LD_LIBRARY_PATH 干不干净，每台都要各自跑一遍 probe_metrics.sh 和 3a′ 才知道。

20想给托管服务调参数，发现没有"编辑/保存"按钮；直接删服务回 409；删掉重建之后 Agent 一重启、服务就再也不回来了三件事叠在一起：① 平台对服务只有 GET / DELETE，没有 PATCH，改参数只能删了重建；② 运行中的服务不能删，要先 stop（否则 409）；③ auto_start 默认是关的，Agent 重启时只会恢复勾了 auto_start 的服务，没勾的会停在 error（健康检查连续 3 次失败）改参数的固定姿势：先停止 → 再删除 → 用新参数重建 → 启动；重建时把 auto_start 和 auto_restart 都勾上。实测勾上之后，Agent 被杀掉再拉起，服务 3 秒自动恢复。重建后记得 ps -ef | grep llama-server 确认只有一个进程、且参数是你新写的（端口被老进程占着时，新服务会直接 crashed）
总结成一句话：手机上尽量只敲无符号的命令（bash install.sh、pgrep -f agent.py 这类）； 凡是带 --、|、'、*、/、" 的，要么点「复制」整段粘贴、要么干脆挪到电脑网页上完成。 名字、备注、改配置这些事，平台网页都能做，手机上不用碰。
