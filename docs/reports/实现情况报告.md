## 0. 结论速览

- **需求书 §1–§9 要求的能力已全部落地**：节点纳管 / 状态监控 / 模型库 / 模型下发 /
  服务管理 / 网关 / 文件管理 / 鉴权与审计 / 前端控制台。
- **里程碑 1~5 全部完成**，验收脚本全绿（逐项数字见 §1）。
- **前端是真的构建过的**：`npx tsc --noEmit` 无错误、`npm run build` 成功，
  `web/dist` 就是平台实际提供的那份产物（`B6.1~B6.3` 三项验收直接验证了这一点）。
- **三件明确不做的事**（不是没做完）：真实公网 P2P/中继、设备重启关机、内建 HTTPS。
  原因见 §2.4，每一条都写了为什么。
- **一件受手机系统限制的事**：Android 非 root 环境下 CPU/GPU/NPU 实时使用率读不到真值（见 §2.1）。

## 2. 做不了 / 有折扣的项（诚实区分）

### 2.1 真机硬件指标真值 —— 手机系统权限所限，**技术不可为**

- **CPU / GPU / NPU 实时使用率**：Android 的 SELinux 屏蔽了 `/proc/stat`、`/sys/class/...` 等路径，
  非 root 环境下读不到。真机实测中这三项持续为 `null`。
- 影响：真机上集群汇总里这部分显示「—」，**不会用旧值或假值冒充**（这是项目硬纪律）。
- 缓解前提：手机 root 或装 Shizuku 并授予 Agent 读取权限；或后续接厂商 NPU SDK。
  当前**模拟器模式**可产出合理数据用于联调与验收。
- **仍能正常拿到的真机指标**：内存、存储、温度、网络收发、电池、进程存活、在线时长。

### 2.2 依赖「人在真机侧操作」的项（平台逻辑已就绪）

- **真机上真正跑起模型服务**：平台侧的启动指令已验证可下发并被 Agent 执行；
  前提是手机 Termux 里确实在跑 `agent.py` 且能执行命令。
  这一步需要按 [`docs/deployment.md`](../deployment.md) 完成接入。
- **防火墙 / 提权 / 系统级改动**：平台**不会也不应**自动改系统防火墙、申请 root。

### 2.3 验证边界：我做了什么、没做什么

- ✅ **跑通了**：模拟 Agent（PC 上 `--simulate`）+ 本地 mock HTTP 服务的端到端链路。
  这条链路覆盖「指令下发 → 状态回写 → 日志 → 网关 → 探活 → 停止 → 崩溃恢复 → 自恢复」全闭环。
- ✅ **前端产物是真的**：`tsc` 与 `vite build` 都实际执行过，`web/dist` 是本次重建的，
  平台根路径返回的就是它（`m2_check` 的 `B6.1~B6.3` 三项直接验证）。
- ⚠️ **未在真机上重跑**：真机接入需要你那边的 Termux 环境，且 §2.1 的指标限制依然存在。
  平台逻辑与模拟环境一致，真机差的是「指标真值」与「真实进程执行」，二者都不是平台代码缺陷。

### 2.4 明确不做的事（不是「没做完」）

| 不做 | 原因 |
|---|---|
| **真实公网 P2P / 中继（ICE/STUN/TURN + Relay）** | 需要真实的公网打洞环境或中继服务器，**本机无法验证**。连接层抽象（`core/transport.py` 的 `Transport`）已就位，换实现不动业务层。写一个无法验证的实现，比不写更糟 |
| **设备重启 / 关机** | Termux 免 root 下没有可用的关机接口。强行「实现」只会是假的 |
| **内建 HTTPS / 证书体系** | 面向局域网部署。Agent 侧已支持 `https://` → `wss://`，需要 TLS 时在前面挂一层反向代理即可 |
| **用户 / 权限体系** | MVP 只有四类令牌，用途隔离、互不通用 |
| **QNN 推理实现** | 本项目只做**手机管理平台**，不做推理引擎。模型怎么跑是设备侧自己的事，平台只负责分发、拉起、探活、统计 |
| **任意远程命令（默认开）** | 默认**关闭**；开启也需白名单 + 全程审计。需求书原文：**禁止 Root Shell 直接暴露公网** |

### 2.5 网关的已知简化（§7 最小可用，明确不是完整网关）

当前网关只做**转发 + 计时 + 计数**，不含：按 key/按服务鉴权、限流、负载均衡、重试、熔断。
这些是后续范围，接口路径与 `gateway_meta` 字段已预留。

主动探活只对**配置了 `health_url` 且节点 IP 平台可达**的服务有效。
模拟节点没有真实服务在监听时探活会失败——设计上它**只记录 `probe_ok`，
不把服务永久判死**，避免误报。

### 2.6 需要人来做决策的项（平台提供能力，不替你拍板）

选哪些节点部署、端口/命令/参数怎么填、互斥组怎么划分、`auto_start` 要不要开——
这些是业务决策，平台只提供入口与校验。

## 3. 交付物与运行方式

- 源码树就是交付物：`server/`（后端）、`node-agent/`（手机 Agent）、`web/`（前端源码 + `web/dist` 构建产物）、`docs/`、`tools/`、启停脚本。
- 打包分发：`python tools/pack_portable.py`（白名单式，排除 `.venv` / `node_modules` / `__pycache__` / `*.db` / 运行时 `data/`）。
- 启动：双击 `启动.bat`，或 `.\start_all.ps1 -BuildWeb`（Windows）/ `BUILD_WEB=1 ./start_all.sh`。
- 控制台：<http://127.0.0.1:8000>；接口文档：<http://127.0.0.1:8000/docs>。

## 4. 一句话总结

**需求书里平台侧该有的能力全部落地，并用 12 个验收脚本 + 前端构建实测过；
卡住的只有三件事——真机 CPU/GPU/NPU 真值（手机系统权限）、公网 P2P/中继（需要外部基础设施）、
以及你还没在自己的手机上把 Agent 跑起来。前两件是环境约束，第三件是你的一次手动接入。**
