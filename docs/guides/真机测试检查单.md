# 真机测试检查单（edge-cluster v0.5.0-m5）

> 适用：Windows 电脑作平台主机 + Android 手机（Termux）作节点，同一局域网。
> 本文所有 `<平台IP>` 都要替换成你电脑的真实局域网 IP。

---

## 0. 先花 30 秒看清边界（别拿没实现的功能当 bug）

**当前版本（0.5.0-m5）能测的**：手机接入、设备信息上报、指标采集（CPU/内存/存储/温度/网络）、
在线离线判定、断线自动重连、告警、历史曲线、节点改名、
模型上传与下发（含 Self Test）、服务启停与日志、网关调用与计数、
设备文件浏览与传输、操作审计查询。

**真机上依然测不了的，以及为什么**（这几项不是 bug）：

| 你可能会去点的地方 | 真实情况 |
|---|---|
| NPU 使用率 / 功耗 | 免 root 拿不到，显示「—」是**诚实留空**，不是采集器坏了 |
| GPU 使用率 | 取决于机型是否暴露 sysfs 节点，多数手机不暴露 |
| 跨公网连接（P2P / 中继） | 本项目不做，只有局域网直连 |
| 设备重启 / 关机 | 免 root 没有可用接口，本项目不做 |
| 控制台上角显示 `v0.5.0-m5` | 与 `curl .../system/health` 的 `version` 字段应一致 |

> `工作室局域网实施步骤.md` 第 12 章写的「轻量 OCR/ONNX 模型部署」「LLM 模型测试」
> 属于**你自己的业务目标**：平台侧的分发、拉起、探活、统计都已经能用了，
> 但具体跑哪个模型、用什么命令，需要你在服务定义里填 —— 平台不会替你挑模型。

## 第 1 阶段：平台侧（电脑上做，约 5 分钟）

### 1.1 拿到平台的局域网 IP

```powershell
ipconfig | Select-String "IPv4"
```

找到你正在上网的那块网卡（WLAN 或以太网），例如：

```
IPv4 地址 . . . . . . . . . . . . : 192.168.1.100
```

**记为 `<平台IP>`。**

> 别拿错：排除 `127.0.0.1`、`169.254.x.x`（没拿到 DHCP）、
> 以及 VMware / VirtualBox / 手机 USB 共享网络那几块虚拟网卡的 IP。

### 1.2 放行 Windows 防火墙（**必须管理员权限**）

右键开始菜单 → **Windows PowerShell（管理员）** → 粘贴这两行：

```powershell
New-NetFirewallRule -DisplayName "EdgeCluster HTTP 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
New-NetFirewallRule -DisplayName "EdgeCluster Discovery 37020" -Direction Inbound -Protocol UDP -LocalPort 37020 -Action Allow
```

判定：不出现红色报错即成功（会回显一行规则信息）。

> 这一步我没法代劳提权，必须你自己开管理员窗口。

### 1.3 启动平台（不起模拟节点）

在项目目录里打开 PowerShell：

```powershell
cd <你解压出来的 edge-cluster 目录>
powershell -ExecutionPolicy Bypass -File .\start_all.ps1 -NoNodes
```

预期：

- 脚本跑完提示平台就绪；
- 浏览器打开 `http://127.0.0.1:8000`，右上角显示 `v0.5.0-m5`；
- **节点数为 0**（`-NoNodes` 就是不要模拟节点，免得你后来分不清哪个是真机）。

> 想对照着看模拟数据也可以去掉 `-NoNodes`，但记住 `phone-01 / phone-02` 是假的。

### 1.4 用手机浏览器先探路（**这步能省你半小时**）

手机连同一个 WiFi，浏览器打开（用系统自带浏览器，别用带「云加速」的 UC/夸克，
它们会把请求走云端代理，内网地址必然打不开）：

```
http://<平台IP>:8000/api/v1/system/health
```

- 返回 `{"status":"ok",...}` → 通了，继续下一阶段。
- 打不开 → 是网络层问题，**先修这个，别急着装 Agent**。按下面逐级定位：

| 现象 | 结论 | 处置 |
|---|---|---|
| 手机 IP 不是同一网段 | 连错网络（光猫 WiFi vs 路由器 WiFi） | 换成同一路由器 |
| 手机也打不开网关 `http://<网关IP>`（如 192.168.100.1） | 网络本身有问题 | 换网络 |
| **网关打得开、平台 IP 打不开** | **客户端隔离（AP 隔离）** —— 校园网/宿舍网几乎必开，只放行网关、禁互访 | 见下方绕过方案 |

> 别用 ping 判断：Windows 防火墙默认禁 ICMP 回显，手机 ping 电脑不通**不代表** 8000 端口不通。

**绕过 AP 隔离：让手机连电脑开的热点**（5 分钟，100% 有效）

1. 电脑：设置 → 网络和 Internet → **移动热点** → 打开（"共享我的互联网连接"选 WLAN）
2. 手机：连上这个热点（关掉原来的校园网 WiFi）
3. 电脑执行 `ipconfig | Select-String "IPv4"`，**本机无线网卡 `WLAN` 的 IP 就是新的 `<平台IP>`**，手机连上热点后与它同网段
4. 手机浏览器打开 `http://<新平台IP>:8000/api/v1/system/health`

平台监听 `0.0.0.0`（通配所有网卡），**不用重启平台**；防火墙规则 Profile=Any，新网卡同样生效。

> 电脑开热点失败时的退路：**手机开热点、电脑连上去**，然后用电脑在新网段里的 IP 访问。
> 平台同样不用重启。

## 第 2 阶段：手机侧（每部手机重复一遍）

### 2.1 装 Termux

1. 从 **F-Droid** 装 Termux（Google Play 版已停维护，别装）。
2. 可选：同时装 **Termux:API**（读温度/电量）和 **Termux:Boot**（开机自启）。
3. 打开 Termux：

```bash
pkg update -y && pkg upgrade -y
```

### 2.2 把 Agent 拷到手机

电脑端：把 `node-agent` 整个文件夹压成 `node-agent.zip`，用数据线 / QQ / 微信传到手机 Download。

手机 Termux：

```bash
termux-setup-storage                      # 弹系统权限框，点「允许」
find /sdcard/Download -maxdepth 4 -name "agent.py" 2>/dev/null   # ① 不管放哪，先定位
cp -r <上面查到的目录> ~/node-agent                               # ② 拷进 Termux 家目录
cd ~/node-agent && ls                                            # ③ 确认
```

应看到 `agent.py`、`install.sh`、`config.toml`、`agent_metrics.py` 等。

> **放在 Download 里、或者自己新建了文件夹，路径对不上时别猜** —— 用上面的
> `find /sdcard/Download -maxdepth 4 -name agent.py` 直接问出来它在哪，把查到的那一行目录
> 原样填进第 ② 步。Termux 的家目录 `~`（`/data/data/com.termux/files/home`）才是 Agent 该待的地方：
> 共享存储（`/sdcard`）是模拟的 FAT 分区，没有 Linux 权限位、部分挂载带 `noexec`，
> 在原地直接跑容易出现莫名其妙的问题，**所以一定要拷进 `~` 再跑**。
>
> **`cp -r A B` 里 B 是"复制成什么名字"，不是"复制到哪个目录里"。**
> 所以 `~/node-agent` 是你给新目录起的名字（`~` = Termux 的家目录），它**不需要事先存在**，
> 更不是去 node-agent 里面找 edge-cluster。名字随便起，这里跟源目录同名最好认。
>
> 如果传的是 zip，`ls /sdcard/Download/` 看到的会是 `node-agent.zip` 而不是文件夹 ——
> 先用手机文件管理器解压，或在 Termux 里 `pkg install unzip && cd /sdcard/Download && unzip node-agent.zip`。
>
> 只需要 `node-agent` 这一个目录，别的都不用拷。

### 2.3 一键安装并启动（节点名必填，两部手机不能同名）

`config.toml` 默认 `name = "phone-02"`，两部手机都用它就分不清谁是谁。

```bash
cd ~/node-agent
bash install.sh --token edge-cluster-dev-token --platform http://<平台IP>:8000 --name mi13-lab-01
```

第二部手机换个名字，例如 `--name redmi-k60-desk`。

> 如果你的 `install.sh` 是改之前的老版本（不支持 `--name`），就先手工改名再装：
> ```bash
> sed -i 's/^name = .*/name = "mi13-lab-01"/' config.toml && grep '^name' config.toml
> bash install.sh --token edge-cluster-dev-token --platform http://<平台IP>:8000
> ```

它会自动：装 python 与依赖 → 写 token 和平台地址 → 申请存储权限 → 申请唤醒锁 →
写保活片段 → 装开机自启 → 启动 Agent → 打印最近日志。

> 第一次建议**显式给 `--platform`**，出问题好定位。
> 想顺带验证 UDP 自动发现，第二部手机可以省略这个参数跑一次，能连上就说明发现功能是好的。

### 2.4 立刻验证（三条命令定生死）

```bash
pgrep -f agent.py                    # ① 应输出一个数字 PID
ls ~/node-agent/logs/                # ② 看真实日志文件名
tail -n 30 ~/node-agent/logs/<你的节点名>.log
```

日志文件名 = 你设的 name，比如 `mi13-lab-01.log`
（**不是 `agent.log`**，旧文档这处写错了，已修）。

③ 日志里应出现 `平台确认注册成功`。

平台侧：控制台 → 节点，应看到这台手机，绿色在线。

### 4.2 真机才能验的那几件事（**A8 的正文**）

模拟节点能验平台的调度、状态机、令牌、进度回传，但验不了 Termux 下的
`Popen` 权限、端口绑定、路径、内存限制、被系统杀进程。下面这几条**只有真手机能暴露**。

**先用一个"假模型"就够了，不需要真的 QNN 模型** —— 这一段验的是"文件能不能安全地送过去、
失败了能不能安全地退回来"，跟模型内容无关（本项目也不做推理实现）。

在**电脑上**造一个几百 KB 的假模型：

```bat
:: 在项目根目录执行
.venv\Scripts\python -c "open('fake-model.bin','wb').write(bytes(range(256))*2000)"
```

| # | 操作 | 通过标准 | 不通过先看 |
|---|---|---|---|
| **T11** | 模型页上传 `fake-model.bin`（名称随意，如 `真机-假模型`）→ 部署页建任务，下发到这台手机 | 节点进度条**逐秒真实推进**；结束后状态 `就绪`；节点详情页能查到该模型 | 平台日志里的 `deploy_queue`；手机 `ls ~/node-agent/models` |
| **T12** | 手机 Termux 里 `sha256sum ~/node-agent/models/fake-model.bin`，和模型页显示的 sha256 比 | **完全一致** —— 说明落盘的是完整文件、没截断 | 不一致说明传输被中途打断却判定成功了，属于严重缺陷，请记录 |

| **T14** | 接着 T13，手机 Termux 里 `sha256sum ~/node-agent/models/fake-model.bin`，再和模型页显示的比 | **和 T12 那次一模一样** —— 旧文件被逐字节还原了 | 若 sha 变了 = 回滚没生效，请连同标签内容一起记录 |
| **T15** | 服务页新建服务，启动命令填一个长跑命令（如 `python3 -c "import time;time.sleep(3600)"`），启动 | 状态变 `运行中`，有 PID；手机 `pgrep -f sleep` 有输出 | 平台日志 `service`；手机 `~/node-agent/logs/` |
| **T16** | 手机上 `pkill -f "time.sleep"` 杀掉它 | **十几秒到一分钟内**平台自己发现并**自动拉起**（状态回到 `运行中`，PID 变了）；手动停一次则不会自己起来 | 服务看门狗日志 `watchdog` |
| **T17** | 文件页浏览手机目录 → 往手机传一个小文件 → 再把它拉回来 | 两端 sha256 一致；**同名的半截传输不会出现在列表里** | 传输令牌与沙箱白名单 |
| **T18** | 服务运行中，从电脑 `curl http://<平台IP>:8000/api/v1/gateway/<service_id>/...`（按服务定义的 endpoint 填） | 能拿到服务返回；总览页的请求量/延迟 +1 | 网关只做转发，不存在的路径会 404 属正常 |

**T13 怎么判**（这一条是本检查单里最值得认真做的一条）：

- ✅ **通过**：任务显示失败，标签写「还原 N 个被覆盖的文件」，且 T14 的 sha 与 T12 相同 ——
  说明"部署失败"和"设备没被弄坏"这两件事同时成立。
- ✅ **也算通过**：标签写「无需还原（…）」，说明失败发生在改动文件之前，旧文件一个字节没动。
- ❌ **不通过**：标签是**橙色**的「回滚未完整完成：…」，或者根本没有标签，
  或者 T14 的 sha 变了。请把标签原文和 sha 一起记下来。

> 把 Self Test 改回空、重新下发一次，让这台手机回到 `就绪`，再继续后面的测试。

## 附：指标探针 `probe_metrics.sh`（T3.5 详解）

**为什么要跑它**：Android 8+ 的 SELinux 会禁掉一部分 procfs / sysfs 文件，
而**每台机器禁的不一样**（取决于内核、厂商 ROM、Android 版本）。这个脚本会逐个探测
约 28 个候选数据源，告诉你**这台手机到底能读什么** —— 采集降级链靠它来定，不靠猜。

```bash
cd ~/node-agent
bash probe_metrics.sh
```

**输出长这样**：

| 标记 | 含义 | 处理 |
|---|---|---|
| `[OK ]` | 读得到，有值 | 采集直接用它 |
| `[NO ]` | 文件不存在 | 这台机器的内核没暴露这个接口，跳过 |
| `[ERR]` | 存在但读不了 | **被 SELinux 拦了**，走降级链 |
| `[EMP]` | 能读但是空的 | 视同不可用 |

末尾会汇总 `可用 N 项 / 不可用 M 项`。

**已知结论（可以先对照）**：

| 数据源 | 免 root Android 上的典型结果 |
|---|---|
| `/proc/stat`（CPU 使用率） | ❌ 被封 —— 这是平台 CPU 显示 `—` 的根本原因 |
| `/proc/loadavg`（负载） | ❌ 被封 |
| `/proc/net/dev`（流量） | ❌ 被封 |
| `/proc/self/stat`（**本进程** CPU） | ✅ 读自己不受限制，真机上唯一稳的 CPU 真值 |
| `/proc/meminfo`（内存） | ✅ 正常 |
| `/sys/class/thermal/*/temp`（温度） | 🟡 视机型 |
| `cpufreq/scaling_cur_freq`（频率） | 🟡 视机型 |
| `dumpsys` | ❌ Termux 里通常不在 PATH（**这是正常的**，不是故障） |

**跑完请把输出贴回来** —— 它决定 `agent_metrics.py` 的降级链在这台机器上该按什么顺序取，
也决定了 T8 里"哪些曲线断点是正常的"。

| 现象 | 一条命令定位 | 处置 |
|---|---|---|
| 手机完全连不上 | 手机 Termux：`curl -s http://<平台IP>:8000/api/v1/system/health` | 不通 = 网络/防火墙；通 = 看下一步 |
| 连上了但不注册 | `tail -n 50 logs/<节点名>.log`（见 2.4） | 日志有「鉴权失败」→ token 不一致 |
| token 不一致 | 比对 `server/config.toml` 与手机 `config.toml` 的 `token` | 改成一样，重启双方 |
| UDP 发现失败 | 平台是否已启动、是否同网段、路由器 AP 隔离 | 用 `--platform http://<平台IP>:8000` 直连兜底 |
| 杀掉 Agent 后还显示在线 | `pgrep -f agent.py` | 有 PID 说明子进程没死透，必须 `pkill` 后再确认 |
| 出现重复节点 | 平台节点列表 | 每部手机的 `--name` 必须固定不变 |
| 指标全是「—」 | 见 §0 | 多数是设备不暴露该接口，属正常 |
| 曲线中间断开 | — | 断点 = 那一刻没采到，**不是 0** |
