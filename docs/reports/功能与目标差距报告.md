# 功能与目标差距报告

> 生成于 2026-10-06。回答一个问题：**这个平台现在离「目标」还差多少。**

## 一句话结论

**核心功能已经全部做完、且在模拟节点上验收通过；真正的差距只剩 5 个「可以做但还没做」的小项，其中 4 个是可选的锦上添花，1 个（真机验证）是必须补的窟窿。** 换 Rust 是另一条独立的路，跟「功能差距」没有关系。

## 二、与目标的差距（分三类看，别混）

### A 类：可以做、还没做（5 项）

| # | 缺什么 | 影响 | 建议 |
|---|---|---|---|
| A2 | 用户与权限体系（无登录、无角色） | 单团队够用；多人分权才需要 | 不急 |
| A3 | 内建 HTTPS | 放 Nginx/Caddy 后面即可，Agent 已支持 wss | 不急 |
| A6 | 限流/负载均衡/熔断 | 超出需求边界 | 不急 |
| A7 | 多实例/磁盘配额 | 单机场景够用 | 不急 |
| **A8** | **真机端到端验证** | **当前最大未知数：所有绿灯都在模拟节点上跑的，真机 Termux 的进程托管/文件管理/下发还没被真人验证过** | **最该做** |

### B 类：环境受限、做不了（6 项）

跨公网 P2P、中继服务器、CPU/负载/网络流量真值、NPU 使用率、设备重启关机、自动改防火墙。真因是：要么需要公网服务器，要么 Android SELinux 封禁，要么是安全红线。

### C 类：设计取舍、决定不做（5 项）

ADB 接入运行时架构、Root Shell 暴露、任意远程命令默认开启、QNN 推理实现、systemd/root 常驻。每一条都是需求书明令的红线或「平台永不主动连手机」这条核心约束的必然结果。

---

## 三、换 Rust 是另一回事（不影响上面的差距）

Rust 改写**不会缩小任何功能差距** —— 它只是把已经完成的功能换一种语言重做一遍。时间 2~4 周、token 约 3000万~8000万（折合 DeepSeek 公开价约 30~100 美元）。**钱不是问题，时间和「把测过的代码砸掉重写」的风险才是。**

---

## 四、结论与优先级

1. **最该做的是 A8 真机验证** —— 这是唯一「功能真缺」的地方，而且你已经装好 Termux + Codex、模型也下好了，只差照着 `真机测试检查单.md` 走一遍。
2. A2/A3/A6/A7 都是锦上添花，单人/单机场景用不上。
3. Rust 改写优先级最低 —— 等真机跑通、真有人用了，再决定要不要为了「分发方便」换栈。
